# Аудит безопасности — 2026-11-01

Что проверено: весь серверный код (`apps/server/src`: вход, токены, админка, вебхук бота, оплата Stars, Premium, покупки, загрузки, озвучка, лимиты), зависимости (`npm audit`), заголовки и выдача статических файлов, места в веб-клиенте, где пользовательские данные попадают в навигацию, внешние ссылки и HTML. Метод: чтение кода + проверка гипотез тестами. Каждое исправление держится тестом (`apps/server/test/security.test.ts`, 10 тестов); главный из них проверен «мутацией» — со старым кодом он падает.

Чего аудит **не** охватывает: настройки аккаунта Cloudflare и Telegram (двухфакторная защита, доступы людей, правила WAF), приватность бакета R2 на стороне Cloudflare, ротацию секретов, резервные копии D1, реальные устройства. Это перечислено в разделе «Что сделать вам».

## Проверено, замечаний нет

- **Вход Telegram:** подпись HMAC, сравнение за постоянное время, срок `auth_date` (24 ч). Токен подписан HMAC, срок 7 дней; токены разных видов не подменяют друг друга (`typ`, `k`).
- **Вебхук бота:** секрет хранит сервер, сравнение за постоянное время, повторная доставка `update_id` не обрабатывается дважды.
- **Оплата Stars:** Premium выдаётся только после `successful_payment` и только если совпали счёт, пользователь, тариф, валюта и сумма; идемпотентность по `charge_id`; платёж, не совпавший со счётом, возвращается автоматически; возврат снимает Premium.
- **Premium на сервере:** доступ к урокам, сценам Premium и пропуску проверяется сервером, клиент права не решает.
- **Деньги игры:** гонки покупок закрыты (`CHECK balance >= 0`, уникальный ключ покупки, список и покупка в одном пакете D1); награды идемпотентны по ключу.
- **SQL:** везде параметры; единственное динамическое имя таблицы — константа.
- **Админка:** роль проверяется на каждом маршруте, все изменения пишутся в журнал, администратор проверяется в базе при каждом запросе (отключение действует сразу).
- **Озвучка:** файл из R2 отдаётся только по строгому адресу из 64 hex-символов; провайдеры озвучки не вызываются из запросов игроков; квоты и общий дневной предел символов.
- **Произношение:** подписанная попытка привязана к пользователю, сессии и заданию, живёт 5 минут и принимается один раз.
- **Веб-клиент:** единственное `dangerouslySetInnerHTML` рисует статичные значки; переходы по `start_param` идут только через белый список маршрутов; внешних адресов из пользовательских данных нет.
- **Данные пользователя:** экспорт и удаление аккаунта работают, платежи при удалении обезличиваются.

## Принятые риски (осознанно оставлено)

- **`DEV_AUTH=true` на staging** допускается документом `docs/STAGING.md` (явная переменная, тест `staging.test.ts`): staging без cron, без боевого бота, со своей базой. Риск — забыть выключить, тогда любой войдёт под выдуманным `id` в тестовую базу. Рекомендация: включать только на время проверки и не хранить в постоянных переменных. В production вход без Telegram выключен всегда.
- **PBKDF2 20 000 итераций** у паролей админов: потолок по времени процессора бесплатного Worker. Смягчено блокировкой подбора (п. 2). Рекомендация: поднять до 100 000 на платном плане и включить двухфакторную защиту админки.
- **initData живёт 24 часа, токен — 7 дней**, отзыв только через блокировку (кэш 30 с). Для Mini App приемлемо; сократить после проверки на устройствах (повторный вход при долгой сессии использует исходный `initData`).
- **Токен в `localStorage`.** Защита — отсутствие XSS-приёмников и (рекомендуется) CSP.
- **`/api/health` без входа** показывает версию, имя миграции, состояние бота и счётчики озвучки. Нужен для проверки выкладки с телефона; секретов нет.
- **Снятие Premium в админке** (`revoke`) не отменяет подписку Stars в Telegram: списания продолжатся. Для возврата денег есть `payments/refund`. Если нужно «снять и больше не списывать» — решение владельца, тогда добавим отмену подписки в Telegram.

## Что сделать вам (в моём доступе этого нет)

1. **Cloudflare → правило ограничения запросов (WAF)** на `/api/admin/login` и `/api/auth/telegram`: это самый надёжный слой, он общий для всех изолятов. Мои счётчики его дополняют, но не заменяют.
2. **Двухфакторная защита** на аккаунтах Cloudflare, GitHub и Telegram-бота; проверить, кому выданы доступы.
3. **R2 `polski-go-audio` приватный**, публичный доступ выключен (файлы отдаёт только Worker).
4. **Секреты** (`SESSION_SECRET`, `TELEGRAM_BOT_TOKEN`, `ADMIN_PASSWORD`, ключи озвучки) — перевыпустить при смене людей; `SESSION_SECRET` не короче 32 символов (сервер без этого не стартует).
5. **Резервные копии D1:** включить и проверить восстановление (Time Travel) — отдельная проверка до публичного запуска.
6. **CSP для Mini App** — после проверки на реальном iPhone и Android. Черновик: `default-src 'self'; script-src 'self' https://telegram.org; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; media-src 'self' blob:; connect-src 'self'; frame-ancestors https://web.telegram.org https://webk.telegram.org https://webz.telegram.org`. Включать сначала как `Content-Security-Policy-Report-Only`, иначе можно сломать приложение в Telegram.
