## Реальная навигация из Telegram в React Mini App

Нельзя ограничиться нарисованными кнопками. Каждая `inline_keyboard` должна содержать живые `web_app`-кнопки с HTTPS URL и проверенными переходами. Предлагаемый стабильный контракт: `?bot_screen=learn|map|dictionary|slang|quests|profile|achievements|settings|grammar` при том же `WEB_APP_URL`; на клиенте — whitelist и единоразовая навигация `navigate(route, {replace:true})` после загрузки пользователя. Поддержать query, если `WEB_APP_URL` уже содержит параметры, и вложенный base path.

Пример: `?bot_screen=map` должен действительно открыть `/map` внутри Mini App после аутентификации и онбординга; для новичка сначала корректный онбординг, затем целевой экран без потери состояния.

Не путать новый `bot_screen` с `startapp`, `start_param`, `ref_`, `story_` и `premium`. Существующие реферальные deeplinks (`https://t.me/<bot>/<shortname>?startapp=ref_<code>`) остаются работоспособны. Если `/start ref_...` открывается через ссылку на бота, проверить сохранение реферера не только через клиентский URL, но через настоящие проверенные серверные данные. Избегать `web_app` в групповых чатах (этот тип кнопок доступен в личном чате). Проверить iOS/Android.

Нужно, чтобы сообщение содержало фото, текст и кнопки; не отправлять сообщения дважды при повторной доставке одинакового `update_id` от Telegram. Для каждой команды, включая `/help` и `/stop`, делать понятные безопасные ответы. Обрабатывать также `/lesson@BotName`, `/start ref_CODE`, неизвестные команды — выдавать справку.

## Бонус: визуальные напоминания
