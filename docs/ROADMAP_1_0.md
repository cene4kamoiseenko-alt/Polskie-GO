# POLSKI GO 1.0 — дорожная карта и состояние работ

Единый файл состояния программы «комплексное развитие, оптимизация и подготовка к версии 1.0» (ТЗ владельца 2026-11-28).
Обновляется после каждого этапа и перед сжатием контекста. После сжатия работа продолжается с раздела «Следующая задача»,
аудит заново не делается.

**Правила программы** (из ТЗ): работа последовательная, без субагентов; продакшн-база, реальные платежи, необратимые действия и
смена сути продукта — только с отдельного разрешения владельца; пуш — только после «пуш»; ничего не публикуется в канал без
одобрения; платных ИИ-вызовов на сервере и в приложении нет; цены, подписки и платёжная механика не меняются; существующие тесты
не отключаются; force push запрещён. Автоматические проверки текста — не проверка носителем языка.

**Навыки (skills).** Есть и применяются: superpowers — using-superpowers, brainstorming, writing-plans, executing-plans,
test-driven-development, systematic-debugging, verification-before-completion, requesting-code-review.
**Нет:** `frontend-design` — в списке навыков отсутствует, его работа не имитируется. Ревью кода — самостоятельное (субагенты
запрещены ТЗ), в отчётах помечается как «self-review».

### Этап 1.2 — скорость и мониторинг (2026-11-28)
- **Аудит API** (`scripts/api-audit.ts`: задержка на каждое обращение к D1): запросы делают 1–7 обращений, подряд — 1–4; главная
  причина медленных ответов была в расстоянии до базы (OC), а не в коде → переезд (1.1). N+1 не найдено.
- **`server-timing`** у каждого ответа: время ответа, время ожидания базы (параллельные обращения не складываются), число обращений.
- **Мониторинг** (`services/perf.ts`, миграция `0030_perf`): выборка 5 % запросов API (медленные и 5xx — всегда), замеры приложения —
  запуск (cold/warm) и открытие урока; админка **«Скорость»**: медиана/p95/p99, обращения к базе, ошибки сервера/бота/приложения/
  фоновых задач. Ошибки cron теперь в журнале ошибок (вид «Фоновая задача»), раньше были только в логах Worker.
- **Запуск:** данные главной (`/quests`, `/missions`, `/house`, `/me/stats`) запрашиваются из `index.html` вместе с `/me`, параллельно
  загрузке JS (один раз за запуск, не кеш); словарь выбранного языка — сразу (раньше сперва английский); минимальная заставка 2,4 с —
  только при первом запуске за день (решение — раздел 6).
- **Не сделано:** JS холодного старта 903 КБ при бюджете 776 (было и до программы): ~300 КБ — движок анимаций framer-motion,
  нужный компонентам главной; вынос — отдельная задача P2 (риск для анимаций). Замер «повторный запуск ≤ 1,5 с» у игроков — после
  выкладки по админке «Скорость» (локальный perf с задержкой базы 25 мс: ~1,6 с при CPU ×4 и RTT 80 мс — грубая оценка).
- **Найдено и исправлено после переезда:** сторож staging и локальные команды (`db:local`, нагрузочный тест) знали только имя

## 6. Решения (rulings)

- Минимальная заставка 2,4 с (решение владельца 01.11) — только при первом запуске за день; повторные запуски в тот же день — без
  паузы (ТЗ 1.0: повторный запуск ≤ 1,5 с). Цена: тот, кто открывает игру несколько раз в день, видит заставку коротко. Вернуть — одна
  функция `splashMinMs` в `packages/shared/src/launch.ts`.
- Данные главной из `index.html` — одноразовый ранний запрос, а не кеш: ответ забирается один раз и только на главной. Цена: если
  игрок сразу уходит с главной, четыре лишних запроса за запуск.

- Команды выкладки не переведены на имя привязки `DB`: поведение wrangler для удалённой базы без `database_id` нельзя проверить без доступа к Cloudflare. Вместо этого — `d1-switch.mjs` + проверка согласованности. Цена ошибки: при ручной правке одного места без скрипта тест упадёт до выкладки.
- В техработы GET, которому нужна запись (`/api/quests` и подобные), отвечает 503 «технические работы», а не 200: несколько минут недоступности экрана лучше потерянной записи. Цена: на время переезда (5–10 мин) часть экранов показывает «технические работы».
- Ночная копия без секретов теперь падает (красный крест, письмо GitHub). Цена: письмо каждую ночь, пока секреты не заданы — это и есть цель.
