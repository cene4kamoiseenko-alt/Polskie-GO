# Голосовые задания

## Озвучка

Существующий TTS использует Google, Azure или ElevenLabs с серверными ключами. Ключи не передаются в Mini App. Без них доступны только подтверждённые польские голоса устройства. Если их нет, приложение покажет недоступность, а не прочитает польский текст другим языком.

Цепочка источников в клиенте (`apps/web/src/lib/audio.ts`): записанный файл (`audioUrl`) → серверный синтез `/api/tts` → польский голос устройства. Каждый шаг при ошибке переходит к следующему; ошибка показывается, только если не сработал ни один. Запрет автовоспроизведения не «лечится» другим источником и сразу показывается как есть.

Кеш озвучки: object URL в памяти (в пределах сессии) и Cache Storage `pg-tts-v1` (до 800 фраз, переживает перезапуск Mini App; любая ошибка хранилища — просто промах). Предзагрузка делает не больше 40 сетевых запросов в минуту при лимите `/api/tts` 120 в минуту и не запрашивает уже сохранённое; озвучка по нажатию бюджетом не ограничена.

**Голос устройства при пустом списке голосов** (частый случай в iOS WebView/Telegram). Подготовлены два варианта: строгий — не говорить; мягкий — говорить с `lang=pl-PL` без подтверждённого голоса и пометкой «голос не подтверждён» (`configureAudio({ deviceVoice: 'soft' })`). **Выбран строгий** (по умолчанию): нет доказательств, что WebView без списка голосов всегда читает польским голосом, а чтение польского текста чужим голосом запрещено правилами проекта. Мягкий вариант включать только после проверки на реальных устройствах.

Проверять в нужной среде: `/api/me` → `audio`, авторизованный GET `/api/tts/status`, затем реальный запрос `/api/tts?text=Dzień%20dobry&rate=normal` и кнопка проверки в настройках. Статус configured подтверждает только конфигурацию, не успешный ответ провайдера. Проверьте обычную/медленную речь и воспроизведение на целевом телефоне.

## Запись с серверным распознаванием

Добавлен дополнительный вариант для WebView, в котором не работает браузерный SpeechRecognition. По умолчанию серверное распознавание выключено. Подготовленная интеграция использует Azure Speech и включается владельцем среды явно:

- `AZURE_STT_ENABLED=true`;
- `AZURE_SPEECH_KEY` — серверный секрет существующего ресурса;
- `AZURE_SPEECH_REGION` — регион этого ресурса.

Само наличие ключа для озвучки не включает запись или серверное распознавание. В этой работе внешний сервис не активировался, запросы с реальной оплатой не выполнялись.

Авторизованный `/api/speech/status` показывает конфигурацию. После включения клиент выбирает обычную запись микрофона вместо браузерного распознавания. HTTPS обязателен, кроме localhost. Запись начинается только по нажатию и разрешению пользователя. Не включайте Permissions-Policy, запрещающую microphone самому приложению.

Клиент использует AudioWorklet, приводит запись к WAV PCM16 mono/16kHz и ограничивает её 30 секундами. Кнопка останавливает запись; микрофон освобождается до сетевого запроса. При выходе, пропуске или отмене запись и запрос отменяются. Если разрешение выдано после отмены, полученный поток сразу останавливается.

`POST /api/speech/transcribe` принимает только наш ограниченный формат WAV, требует авторизацию и ограничивает размер и частоту запросов. Сервер передаёт аудио в Azure с языком `pl-PL`. Невалидное аудио, тишина, ошибки провайдера и отсутствие конфигурации возвращают ошибки, а не выдуманный результат. Аудиозаписи и расшифровки этим маршрутом не сохраняются в БД и не выводятся в лог.

Это проверка распознанного текста, а не фонетическая оценка акцента. После ответа провайдера результат сравнивается с учебной фразой. Процент совпадения не является оценкой произношения носителем.

Если серверный вариант выключен, сохраняется браузерный SpeechRecognition с остановкой, отменой и тайм-аутом. При отсутствии обоих вариантов пользователь может продолжить курс без фиктивного зачёта записи.

## Что проверено

Автотесты проверяют WAV, формат/язык/ошибки серверного запроса, авторизацию и ограничение тела, остановку/отмену микрофона, в том числе позднее разрешение. В браузере с реальной локальной D1 проверены повтор после имитации тишины и отправка распознанного текста в API.

Реальные микрофон, Azure-распознавание и Telegram на iPhone требуют проверки владельцем среды. Заглушка провайдера и имитированный микрофон не доказывают их работу.

Документация протокола: https://learn.microsoft.com/en-us/azure/ai-services/speech-service/rest-speech-to-text-short
