# Голосовые задания

## Озвучка

Существующий TTS использует Google, Azure или ElevenLabs с серверными ключами. Ключи не передаются в Mini App. Без них доступны только подтверждённые польские голоса устройства. Если их нет, приложение покажет недоступность, а не прочитает польский текст другим языком.

Провайдер выбирается переменной `TTS_PROVIDER`: `auto` (по умолчанию — первый с ключом), `google`, `azure`, `elevenlabs` или `off`. Что реально играет, официальные списки голосов, цены и слепой тест — в `docs/POLISH_TTS_BENCHMARK.md`.

**Подключение Google TTS по шагам** (проект, оплата, ключ, Cloudflare, сравнение голосов в админке, прогрев, проверка на телефонах, лимиты) — `docs/GOOGLE_TTS_SETUP_RU.md`. Кроме квоты на игрока действует суточный лимит платной озвучки на весь проект: `TTS_GLOBAL_DAILY_CHARS`, по умолчанию 30 000 символов (таблица `tts_spend`, миграция 0010). Сверх него `/api/tts` отвечает `429 tts_budget_exceeded` без запроса к провайдеру, клиент говорит голосом устройства. Эмодзи в тексте задания перед озвучкой убираются (`speechText`).

Цепочка источников в клиенте (`apps/web/src/lib/audio.ts`): записанный файл (`audioUrl`) → серверный синтез `/api/tts` → польский голос устройства. Каждый шаг при ошибке переходит к следующему; ошибка показывается, только если не сработал ни один. Запрет автовоспроизведения не «лечится» другим источником и сразу показывается как есть.

Кеш озвучки: object URL в памяти (в пределах сессии) и Cache Storage `pg-tts-v2` (до 800 фраз, переживает перезапуск Mini App; любая ошибка хранилища — просто промах). Ключи обоих кешей и адрес запроса содержат отпечаток серверного голоса (`/api/me` → `audio.fingerprint`), так что после смены голоса старые записи не играют. Старый `pg-tts-v1` удаляется один раз. Предзагрузка делает не больше 40 сетевых запросов в минуту при лимите `/api/tts` 120 в минуту и не запрашивает уже сохранённое; озвучка по нажатию бюджетом не ограничена.

**Голос устройства при пустом списке голосов** (частый случай в iOS WebView/Telegram). Подготовлены два варианта: строгий — не говорить; мягкий — говорить с `lang=pl-PL` без подтверждённого голоса и пометкой «голос не подтверждён» (`configureAudio({ deviceVoice: 'soft' })`). **Выбран строгий** (по умолчанию): нет доказательств, что WebView без списка голосов всегда читает польским голосом, а чтение польского текста чужим голосом запрещено правилами проекта. Мягкий вариант включать только после проверки на реальных устройствах.

Проверять в нужной среде: `/api/me` → `audio`, авторизованный GET `/api/tts/status`, затем реальный запрос `/api/tts?text=Dzień%20dobry&rate=normal` и кнопка проверки в настройках. Статус configured подтверждает только конфигурацию, не успешный ответ провайдера. Проверьте обычную/медленную речь и воспроизведение на целевом телефоне.

## Запись с серверным распознаванием

Добавлен дополнительный вариант для WebView, в котором не работает браузерный SpeechRecognition. По умолчанию серверное распознавание выключено. Подготовленная интеграция использует Azure Speech и включается владельцем среды явно:

- `AZURE_STT_ENABLED=true`;
- `AZURE_SPEECH_KEY` — серверный секрет существующего ресурса;
- `AZURE_SPEECH_REGION` — регион этого ресурса.

Само наличие ключа для озвучки не включает запись или серверное распознавание. В этой работе внешний сервис не активировался, запросы с реальной оплатой не выполнялись.

### Google Speech-to-Text (второй провайдер, 2026-10-27)

Код готов и покрыт тестами с подменённым Google (`apps/server/test/stt.test.ts`). Реальный Google STT из этой среды не вызывался: доступа к Google Cloud нет, биллинг не включался.

Переменные (секреты Worker, в клиент не попадают):

| Переменная | Значение |
|---|---|
| `GOOGLE_STT_ENABLED` | `true` — явное включение. Без него ни ключ STT, ни ключ TTS запись не включают |
| `GOOGLE_STT_API_KEY` | отдельный API-ключ. Если не задан, после явного флага используется `GOOGLE_TTS_API_KEY` — тогда у ключа должен быть разрешён и Speech-to-Text API |
| `GOOGLE_STT_MODEL` | необязательно. По умолчанию модель не передаётся (Google берёт стандартную для pl-PL). `latest_short` подходит для коротких фраз, но поддержку pl-PL этой моделью проверить по таблице языков перед включением, иначе каждый запрос вернёт 400 |
| `STT_PROVIDER` | `auto` (по умолчанию: Azure, если включён, иначе Google), `azure`, `google`, `off` — аварийный выключатель |

Запрос: `POST https://speech.googleapis.com/v1/speech:recognize`, ключ — в заголовке `X-Goog-Api-Key` (не в адресе), тело — `LINEAR16`, 16 кГц, mono, `languageCode: pl-PL`, аудио base64. Пустой `results` — «тишина/не распознано» (422), любая ошибка Google — 502 без тела ответа провайдера. Платный счётчик (`STT_DAILY_LIMIT`, по умолчанию 60 записей в день на пользователя) срабатывает только перед реальным запросом к провайдеру.

Подключение владельцем:

1. Google Cloud Console → проект с биллингом (без привязанного биллинга Speech-to-Text не работает даже в бесплатном объёме) → включить **Cloud Speech-to-Text API**.
2. APIs & Services → Credentials → Create API key → Restrict key: API restrictions — только Cloud Speech-to-Text API (и Text-to-Speech, если ключ общий). Application restrictions для Worker не ставить по IP (у Cloudflare нет фиксированного адреса).
3. Бюджет и оповещения: Billing → Budgets & alerts, например на 5 $, чтобы перерасход был виден сразу.
4. Cloudflare → Workers → polskie-go → Settings → Variables and Secrets: `GOOGLE_STT_API_KEY` (Secret), `GOOGLE_STT_ENABLED=true`.
5. Проверка: авторизованный `GET /api/speech/status` → `{ configured: true, provider: "google" }`; затем задание на произношение в уроке на телефоне.

Цена — по данным поиска на 2026-10-27, перед включением сверить на https://cloud.google.com/speech-to-text/pricing: первые 60 минут в месяц бесплатно, далее порядка 0,016 $ за минуту (с согласием на логирование данных дешевле). Наши записи до 30 с; как Google округляет короткие запросы, тоже сверить там же. При 60 записях в день на пользователя бесплатные 60 минут закончатся примерно на 120–360 записях в месяц на весь проект.

Это распознавание слов, а не фонетическая оценка: сервер получает текст и сравнивает его со словами фразы. Правильно распознанное слово не значит правильный акцент; неверно распознанное слово может быть ошибкой распознавания, а не ученика. Интерфейс говорит «распознано», а не «произношение оценено».

Авторизованный `/api/speech/status` показывает конфигурацию. После включения клиент выбирает обычную запись микрофона вместо браузерного распознавания. HTTPS обязателен, кроме localhost. Запись начинается только по нажатию и разрешению пользователя. Не включайте Permissions-Policy, запрещающую microphone самому приложению.

Клиент использует AudioWorklet, приводит запись к WAV PCM16 mono/16kHz и ограничивает её 30 секундами. Кнопка останавливает запись; микрофон освобождается до сетевого запроса. При выходе, пропуске или отмене запись и запрос отменяются. Если пользователь свернул Mini App во время записи (`visibilitychange` → hidden), дорожки микрофона останавливаются сразу, недописанная попытка не отправляется, состояние возвращается в «готово». Если разрешение выдано после отмены, полученный поток сразу останавливается.

`POST /api/speech/transcribe` принимает только наш ограниченный формат WAV, требует авторизацию и ограничивает размер и частоту запросов. Сервер передаёт аудио выбранному провайдеру (Azure или Google) с языком `pl-PL`. Невалидное аудио, тишина, ошибки провайдера и отсутствие конфигурации возвращают ошибки, а не выдуманный результат. Аудиозаписи и расшифровки этим маршрутом не сохраняются в БД и не выводятся в лог.

Это проверка распознанного текста, а не фонетическая оценка акцента. После ответа провайдера результат сравнивается с учебной фразой. Процент совпадения не является оценкой произношения носителем.

**Зачёт и награда только за подтверждённую сервером попытку.** В уроке запись отправляется на `/api/speech/transcribe?session=…&item=…`; сервер проверяет, что это незавершённое задание на произношение в активной сессии этого пользователя, распознаёт запись и возвращает подписанную попытку (HMAC, живёт 5 минут, привязана к пользователю, сессии и заданию, одноразовый nonce хранится в состоянии сессии). `/answer` засчитывает только `{ attempt }`. Текст, присланный клиентом (`{ transcript }` — браузерный SpeechRecognition), — это тренировка: без XP, без ошибки, не входит в точность урока; интерфейс так и пишет.

**Тишина не уходит в платное распознавание**: клиент проверяет, есть ли в записи кадры с голосом (RMS 20-мс кадров, порог ≈ −44 dBFS, `hasVoiceActivity`), и показывает «Тишина». Порог подобран на синтетических сигналах и фейковом микрофоне Chromium, на реальном iPhone не проверялся.

**Состояния микрофона** (видны над кнопкой записи): готово, включение микрофона (с подсказкой разрешить доступ — в этот момент система может спросить разрешение), запись с таймером и уровнем сигнала (значит, доступ получен), обработка, нужно разрешение, тишина, слишком коротко (запись меньше 0,5 с — случайное нажатие; не отправляется), нет сети (показывается ещё до нажатия), сервис не подключён (дальше — тренировка распознаванием устройства, если оно есть), запрещено системой (`service-not-allowed`, бывает в WKWebView), слишком часто, дневной лимит, сервис недоступен, время вышло. В любом состоянии можно пропустить задание — курс не блокируется.

**Квоты платных обращений.** Кроме ограничения частоты в памяти изолята (`rateLimit`, гасит всплески) действует добовая квота на пользователя в D1 (`usage_counters`, миграция 0006): по умолчанию 60 записей на распознавание и 300 новых фраз синтеза (кэшированные фразы не считаются). Меняется переменными `STT_DAILY_LIMIT` и `TTS_DAILY_LIMIT`. Сверх квоты — `429 quota_exceeded`, провайдер не вызывается; озвучка в этом случае переходит на голос устройства, запись — в состояние «лимит на сегодня». Счётчики старше 7 дней удаляет cron.

**Почему «W» звучала как «дужеву».** В конструкторе фраз каждое нажатое слово озвучивается; отдельный токен «W» польский голос читает как название буквы — «duże wu» («большая W»). Одиночные буквы теперь не озвучиваются отдельно: в конструкторе предлог или союз (w, z, i, a, o, u) звучит вместе со следующим выбранным словом, в задании с пропуском — внутри всей фразы. Чужой (русский или английский) голос по-прежнему не используется никогда.

Если серверный вариант выключен, сохраняется браузерный SpeechRecognition с остановкой, отменой и тайм-аутом — как тренировка без XP. При отсутствии обоих вариантов пользователь может продолжить курс без фиктивного зачёта записи.

## Что проверено

Автотесты проверяют WAV, формат/язык/ошибки серверного запроса, авторизацию и ограничение тела, остановку/отмену микрофона, в том числе позднее разрешение, подписанные попытки (повтор, чужие сессия/задание/пользователь, подделка, истечение), квоты и проверку тишины.

`npm run e2e` (Playwright, локальная D1, свободные порты): путь распознавания устройства (события подменены) — тишина без отправки, фраза — тренировка без XP; серверный путь — настоящие `getUserMedia` и AudioWorklet на фейковом микрофоне Chromium (WAV с тоном), Azure подменён в процессе: нет сети, отказ в разрешении, тишина без запроса к STT, сворачивание во время записи (дорожки `ended`, без запроса), слишком короткая запись без запроса, привязанная к заданию запись → подписанная попытка → зачёт с XP.

Реальные микрофон, Azure-распознавание и Telegram на iPhone требуют проверки владельцем среды. Заглушка провайдера и имитированный микрофон не доказывают их работу.
