# Telegram-бот POLSKI GO: команды, картинки, напоминания

Задание владельца — `docs/PROMPT_TELEGRAM_BOT.md` (дословно), ТЗ и комплект — `docs/bot/`. Здесь описано, что реализовано, как это развернуть и что **ещё не проверено**.

> Бот в Telegram обновляется сам после деплоя: в течение 15 минут cron ставит новое меню команд (с `/quiz`), переводит webhook на серверный секрет и включает `callback_query`. Ничего запускать вручную не нужно; проверить — админка → «Бот» или `/api/health`.

## 1. Что умеет бот

Девять команд-карточек и быстрый вопрос `/quiz`. Каждая карточка отвечает **фото 1280×720 + подпись + inline-кнопки**; кнопки в личном чате — `web_app` и открывают нужную вкладку Mini App. Картинка — по языку интерфейса (раздел 2).

| Команда | Картинка | Кнопки (экран Mini App) | Данные |
|---|---|---|---|
| `/start` | `start.jpg` | Начать путешествие (`home`), Мои уроки (`learn`), Карта Польши (`map`) | имя из Telegram; повторно — «С возвращением» + следующий урок |
| `/lesson` | `lesson.jpg` | Продолжить обучение (`learn`), Выбрать город (`map`), Повторить слова (`dictionary`) | реальное название и город следующего урока |
| `/map` | `map.jpg` | Открыть карту (`map`), Мои уроки (`learn`) | — |
| `/words` | `words.jpg` | Словарь (`dictionary`), Сленг (`slang`), Грамматика (`grammar`) | — |
| `/quests` | `quests.jpg` | Мои задания (`quests`), Достижения (`achievements`), Пойти на урок (`learn`) | только реальные активные задания и награды; ничего не выдумывается |
| `/profile` | `profile.jpg` | Профиль (`profile`), Достижения (`achievements`), Продолжить / Начать первый урок (`learn`) | уровень, XP, серия, уроки из БД; новичку — приглашение |
| `/settings` | `settings.jpg` | Открыть настройки (`settings`), Вернуться к урокам (`learn`) | — |
| `/help` | `help.jpg` | Открыть POLSKI GO (`home`), Начать урок (`learn`), Настройки (`settings`) | также ответ на неизвестную команду и на текст в личном чате; после карточки ставится панель быстрых кнопок (как и после `/start`) |
| `/stop` | `stop.jpg` | Настроить напоминания (`settings`), Продолжить обучение (`learn`) | выключает **только** учебные напоминания |
| `/quiz` | тематическая только для ru-тем «покупки / еда / транспорт», иначе текст | варианты ответа (`callback_query`), затем «Следующий вопрос», урок по теме, «Не присылать вопросы» | вопрос, пояснение, XP — из сервера (раздел 1a) |

* **Постоянная панель быстрых кнопок** под полем ввода: 📚 Урок, 🗺 Карта, 📖 Слова / 🎯 Задания, 🏆 Профиль, ⚙️ Настройки / 🧠 Быстрый вопрос (две строки по три и третья с вопросом, на ru/uk/pl/en). Она ставится отдельным коротким сообщением («Быстрое меню внизу…») **после карточки `/start` и `/help`** в личном чате (у сообщения не может быть двух клавиатур) и остаётся в чате (`is_persistent`). Нажатие отправляет обычный текст с подписью; бот узнаёт её на любом из четырёх языков и отвечает карточкой соответствующей команды (картинка + inline-кнопки Mini App). В группах панели нет; сбой отправки панели ответ не ломает и карточку не повторяет. Код: `apps/server/src/bot/panel.ts`. Панель — дополнение к ТЗ по просьбе владельца («удобные кнопки»); inline-кнопки под карточками остаются.
* `/stop` ничего не удаляет: прогресс, серия, Premium сохраняются. Кнопка «Настроить напоминания» открывает настройки, **не включает** рассылку. Ответ «напоминания выключены» уходит только после успешной записи в БД; при сбое БД бот честно пишет, что не получилось (без картинки).
* Реферальные ссылки: `t.me/<бот>?start=ref_CODE` — реферера записывает сервер по подписанному webhook (только в личном чате, формат `ref_[A-Za-z0-9]{1,32}`). Параметр `/start <payload>` (`^[A-Za-z0-9_-]{1,64}$`) попадает в `startapp` кнопки главного экрана, прежние ссылки работают.
* Языки текстов: `ru`, `uk`, `pl`, `en`. Выбор: сохранённая настройка пользователя → `language_code` Telegram → `uk` (язык по умолчанию продукта). Имя экранируется (`<`, `&`, `>`, кавычки; управляющие и bidi-символы убираются; до 64 знаков).
* Группы: `web_app`-кнопки там недоступны, поэтому кнопки — обычные ссылки `https://t.me/<бот>/<приложение>?startapp=screen_<экран>`. Бот отвечает только на команды, адресованные ему (фильтр `@имя` работает, когда задана `TELEGRAM_BOT_USERNAME`).
* Заблокированный (`banned`) пользователь не получает ответов. Сбой БД не лишает ответа: `/start`, `/help`, `/map` и т.п. отвечают без персональных данных; `/profile` не изображает «нет прогресса», а говорит, что не смог загрузить.

Тексты — `apps/server/src/bot/copy.ts` (`COPY[lang]`), каталог — `apps/server/src/bot/catalog.ts`, обработчик — `apps/server/src/bot/handler.ts`, отправка — `apps/server/src/bot/send.ts`, данные — `apps/server/src/bot/data.ts`, меню команд — `apps/server/src/bot/commands.json` (ru/uk/pl/en).

## 1a. Быстрые вопросы `/quiz`

* Банк — 60 вопросов (`apps/server/src/bot/quiz/questions.ts`): покупки 9, еда 9, транспорт 9, город 6, работа 6, здоровье 5, быт 5, грамматика 6, разговор 5; A1 21, A2 29, B1 10; ru/uk/pl/en. Верный вариант хранится первым и перемешивается при отправке.
* Запуск: `/quiz`, кнопка панели «🧠 Быстрый вопрос», ссылка `t.me/<бот>?start=quiz` (из групп), кнопка «Следующий вопрос» и приглашение от бота. Только в личном чате.
* Вопрос: категория и уровень, текст, 3–4 варианта кнопками `qa:<раунд>:<позиция>` (длинные варианты — буквами в тексте), 20 секунд на экране (сервер принимает до 30 — запас на доставку).
* Ответ: сообщение заменяется итогом (верно / нет / время вышло, ваш и правильный вариант, пояснение, XP, сколько ответов сегодня ещё дадут XP), всплывающая подсказка на нажатие. Раунд переходит `OPEN → ANSWERED` условным UPDATE: двойное нажатие, повтор доставки Telegram и одновременные нажатия дают один ответ и одну награду.
* **XP**: +10 за верный ответ вовремя, только за первые **три** в местный день и только пользователю с аккаунтом. Через тот же `grantXp` (журнал `xp_events` с ключом `quiz:<раунд>`, дневная активность, недельная лига), задания «Получи N XP» и достижения — Mini App видит XP сразу. Серия дней от вопроса **не** растёт: её продлевают уроки и миссии.
* **Тренировка не ограничена паузой**: после трёх наград можно отвечать дальше без XP. Защита только от спама — не чаще раза в 4 секунды (двойное нажатие) и не больше 30 вопросов в день.
* **Приглашения** (cron, `bot/quiz/invites.ts`): только тем, кто уже сам отвечал, не выключил вопросы и уведомления; один раз в местный день в 13:00 (или в 17:00, если напоминание стоит на 12–14 часов); не раньше чем через **3 часа** после последнего вопроса; только пока есть XP за ответы; после двух приглашений подряд без ответа — пауза, пока ученик не ответит сам. Приглашение — текст и кнопка, без картинки.
* Таблицы: `bot_quiz_players` (по Telegram id: счётчики дня, награды, недавние вопросы, приглашения), `bot_quiz_rounds` (каждый вопрос; старше 30 дней удаляет cron). При удалении аккаунта удаляются и они.

## 2. Картинки

Файлы лежат в `apps/web/public/bot/commands/` и публикуются Workers Static Assets на origin приложения (`WEB_APP_URL`):

```
https://<origin>/bot/commands/start.jpg   lesson.jpg   map.jpg   words.jpg   quests.jpg
                               profile.jpg settings.jpg help.jpg  stop.jpg
                               reminder-lesson.jpg  reminder-streak.jpg  reminder-return.jpg
```

* Адрес картинки строится как `new URL('/bot/commands/<файл>', new URL(WEB_APP_URL).origin)`. Фото отправляется **только** если адрес — `https` (локально, при `http://localhost`, уходит текст с теми же кнопками). Telegram скачивает файл сам, авторизация не нужна.
* Подпись к фото ≤ 1024 знаков. Если текст длиннее, уходит короткая подпись (первый абзац) и отдельное сообщение с остальным текстом и кнопками.
* Если Telegram отверг сам снимок (HTTP 400/404 и т.п.: адрес недоступен, не JPEG) — тот же текст и те же кнопки уходят обычным сообщением. Блокировка бота (403), лимит (429), сбой Telegram (5xx) и неопределённый исход сети в текст **не** превращаются: иначе пользователь мог бы получить дубль.
* `wrangler.jsonc` использует `not_found_handling: single-page-application`: если файла нет, сервер вернёт `index.html` со статусом 200. Поэтому после деплоя проверять надо **Content-Type: image/jpeg**, а не только 200 (команда ниже).
* Description Picture (картинка в «Что умеет этот бот?») через Bot API не меняется и не затрагивается.

**Честно про набор:** это промежуточный стартовый комплект владельца, часть кадров повторяется (проверено по md5):

| Одинаковые файлы |
|---|
| `start.jpg` = `settings.jpg` |
| `lesson.jpg` = `quests.jpg` = `reminder-lesson.jpg` |
| `profile.jpg` = `reminder-streak.jpg` |
| `stop.jpg` = `reminder-return.jpg` |

Уникальные кадры: `help`, `words`, `map` (и по одному на каждую группу выше). Позже любой файл можно заменить, код не меняется.

**Русский интерфейс — полнокадровые доски владельца** (`apps/web/public/bot/scenes/ru/`, мастера — `docs/design/a10/telegram/*.webp` 1672×941): `start` (/start), `return` (/start для вернувшегося: «Снова тут? Приятно, что ты вернулся!»), `lesson`, `words`, `settings`, а для вопросов `/quiz` — `shopping` / `food` / `transport`. У каждой доски два файла: `<имя>.jpg` 1280×720 (его шлёт `sendPhoto`) и `<имя>@640.jpg` 640×360. Файлы собирает `node scripts/build-bot-images.mjs` только уменьшением Lanczos: без размытия, без заливки полос, без растягивания. Проверка: `npm run assets` (размер, JPEG, дубли по пикселям, резкость краёв). На досках русские заголовки, поэтому uk / pl / en получают кадры без надписей на языке интерфейса (`commands/`).

Старые `ru/*.jpg` (640×360, растянутые, с размытыми боковыми полосами и белой каймой) **удалены**. Для `/map`, `/quests`, `/profile`, `/help`, `/stop` и напоминаний доски в комплекте нет: там нейтральные кадры `commands/*` (резкие), а не подмена плохой картинкой. **Не подключены** доски с живыми данными, которые противоречили бы реальности: «+20 XP» (в квизе 10), «+15 XP» и «WARSZAWA», серия «7 дней», фиксированные штампы паспорта, образец вопроса «Jak się nazywa ten sklep?». Точные имена недостающих файлов и описания сцен — `assets/telegram/asset-manifest.json`, раздел `blocked_scenes`.

## 3. Mini App: параметр `bot_screen`

Кнопка бота открывает `WEB_APP_URL?bot_screen=<экран>`. Белый список (`packages/shared/src/botScreens.ts`): `home` (без параметра), `learn` → `/learn`, `map` → `/map`, `dictionary` → `/dictionary`, `slang` → `/slang`, `quests` → `/quests`, `profile` → `/profile`, `achievements` → `/achievements`, `settings` → `/settings`, `grammar` → `/grammar`.

* Любое другое значение игнорируется (остаёмся на `/`), параметр убирается из адреса.
* Запасной канал для групповых ссылок: `startapp=screen_<экран>`.
* Не смешивается с `startapp` / `ref_` / `story_` / `premium`: рефералы, истории и Premium работают как раньше.
* Новичок сначала проходит знакомство; затем (`Onboarding.finish`) открывается запрошенный экран, а не первый урок. Повторный запуск идёт прямо на экран. Пока маршрут не применён, вместо `Routes` показывается скелетон (без мелькания главной).
* Код: `apps/web/src/lib/launch.ts`, `apps/web/src/App.tsx`, `apps/web/src/screens/Onboarding.tsx`.

## 4. Идемпотентность webhook

Таблица `telegram_updates(update_id PK, created_at)`. Обновление-сообщение обрабатывается один раз (платежи не дедуплицируются здесь — их защищает своя логика). При временном сбое Telegram (код 0 / 429 / 5xx) метка снимается и возвращается 503, чтобы Telegram повторил доставку; при 400/403 возвращается 200 без повторов. Сбой самой таблицы не блокирует ответ. Cron удаляет строки старше 3 дней.

Платежи Stars (`pre_checkout_query`, `successful_payment`, `refunded_payment`) остались как были.

## 5. Напоминания (`apps/server/src/jobs.ts`)

Cron `*/15 * * * *`. Три сценария, выбираются по реальным данным:

| Вид | Условие | Картинка | Кнопка |
|---|---|---|---|
| `return` | не заходил ≥ 3 дней | `reminder-return.jpg` | Вернуться в игру (`home`) |
| `streak` | эффективная серия ≥ 2 | `reminder-streak.jpg` | Продолжить серию (`learn`) |
| `lesson` | иначе | `reminder-lesson.jpg` | Продолжить урок (`learn`) |

Правила:
* Только при согласии (`user_settings.notifications_enabled`), в выбранный час и часовой пояс пользователя; не более одного напоминания в день (уникальный ключ `(user_id, kind='daily_reminder', day)` в `notification_log`).
* К тексту добавляется строка про `/stop`.
* Ложной записи «отправлено» нет. Состояния строки `notification_log.status`:

| Статус | Значение |
|---|---|
| `PENDING` | заявка на отправку; аренда (lease) 5 минут, так два параллельных Cron не пошлют дубль |
| `SENT` | Telegram принял; сохраняются метод (фото/текст), `telegram_message_id`, время |
| `FAILED` | точный сбой (429 / 5xx): повтор в тот же местный день, до `NOTIFY_MAX_ATTEMPTS=3`, паузы 5 / 20 минут или `retry_after` |
| `BLOCKED` | 403 (бот заблокирован): пользователь пропускается 30 дней |
| `UNKNOWN` | неопределённый исход (сеть/таймаут, истёкшая аренда): **не повторяется**, чтобы не отправить дубль |
| `SKIPPED` | `day_passed`, `consent_withdrawn` (согласие отозвано), `already_active` |
| `LEGACY` | строки до миграции 0008 |

* Бюджет подзапросов Worker: `SEND_BUDGET=35` вызовов Bot API за запуск (фото + запасной текст = 2).
* Миграция `0008_bot_delivery.sql` **только добавляет**: таблицу `telegram_updates`, колонки `notification_log` (старые строки получают `LEGACY`), индекс. Ничего не удаляет и не переписывает.

## 6. Развёртывание

1. **Тесты, typecheck, content-lint** перед пушем (см. ниже). Пуш в ветку запускает Cloudflare Workers Builds и деплоит.
2. Деплой (`npm run deploy:cf`, его же запускает Workers Builds) идёт так: (1) `wrangler d1 time-travel info` — в журнал сборки пишется текущая закладка Time Travel (точка восстановления); (2) миграции D1 **до** выкладки кода — миграции только добавляют таблицы, старый код их не замечает, а если миграция упадёт, деплой остановится и продолжит работать прежняя версия; (3) `wrangler deploy`; (4) недостающий контент (`seed.sql`). Откат базы: `wrangler d1 time-travel restore polski-go --bookmark=<закладка из журнала>` (или `--timestamp=<ISO>`), окно — 7 дней на бесплатном плане, 30 на Workers Paid. Откат кода — Cloudflare → Worker → Deployments → предыдущая версия.
3. Переменные Cloudflare (не менять без причины): `WEB_APP_URL` (полный адрес с `https://`; если указан без схемы или с `http://`, сервер и `bot:setup` сами приведут его к `https://`, `localhost` остаётся на http и тогда фото не уходят), `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `TELEGRAM_APP_SHORT_NAME`. `TELEGRAM_WEBHOOK_SECRET` нужен только до первой смены секрета (дальше секрет webhook хранит сервер, раздел 6b); `BOT_SETUP_KEY` — необязательный ключ страницы `/telegram/setup`.
4. После деплоя владелец один раз запускает локально (секреты берутся из окружения/`.env`, в вывод не попадают):
   ```
   WEB_APP_URL=https://<origin> TELEGRAM_BOT_TOKEN=… npm run bot:setup -w @polski-go/server
   ```
   Что делает: `setMyCommands` — девять команд и `/quiz` (ru по умолчанию + uk/pl/en) и `setChatMenuButton` (кнопка запуска Mini App). Затем только читает `getWebhookInfo` / `getMyCommands`. Запускать не обязательно: меню после деплоя ставит cron.
5. Флаги:
   * `--dry-run` — показать вызовы без сети (токен не нужен);
   * `--webhook` — **больше не поддерживается**: секрет webhook генерирует и хранит сервер, человек его не знает. Webhook ставит админка или cron (раздел 6b);
   * `--description` — перезаписать описание бота текстом по умолчанию. Без флага описание, заданное вручную в BotFather, остаётся нетронутым.
6. Скрипт **не** меняет токен, webhook, About, Description Picture.
6a. **Без компьютера.** Админка `https://<origin>/admin/` (SUPERADMIN) → «🤖 Бот»: «Проверить» (только getMe и getWebhookInfo), «Настроить бота» (команды ru + uk/pl/en, кнопка меню, webhook с `message`, `callback_query`, `pre_checkout_query`), «Сменить секрет webhook». Каждое действие пишется в журнал админки (без секретов). Запасной путь — страница `https://<origin>/telegram/setup`: форма, ключ (`BOT_SETUP_KEY`) уходит **заголовком POST-запроса, не в адресе**; не больше 10 попыток за 10 минут с адреса. Ссылки вида `?key=…` больше не принимаются (ключ попадал в историю браузера и журналы). Прежний `TELEGRAM_WEBHOOK_SECRET` открывает эту страницу, только пока сервер не перешёл на свой секрет.
6b. **Секрет webhook** (`bot/webhook-secret.ts`). Telegram присылает его в `X-Telegram-Bot-Api-Secret-Token`; кто его знает, может подделать любое обновление. Поэтому секрет генерирует сервер (32 случайных байта, base64url — формат Telegram `[A-Za-z0-9_-]{1,256}`), хранит в D1 (`app_state`) и отдаёт только Telegram. Смена — поколениями: новый действует сразу; прежний (или значение из переменной) принимается, пока Telegram не подтвердил новый, и ещё 10 минут после. Если Telegram явно отказал — прежнее состояние возвращается; если ответ потерялся — работают оба, а cron повторяет `setWebhook` и подтверждает. Первую смену (с переменной, которая могла утечь, на серверный) cron делает сам в первые 15 минут после деплоя; дальше секрет меняет только админ. Защита не держится на одном секрете: дубли `update_id` отбрасываются, ответ на вопрос принимается только от его владельца и один раз, Premium включается только по нашему счёту (тот же payload, пользователь, тариф, валюта XTR и сумма).
6c. **Самопроверка cron** (`bot/maintain.ts`, раз в час и сразу после выкладки новой версии настройки): `getWebhookInfo`; если webhook не получает `callback_query`, получает 401 после последней настройки или новый секрет не подтверждён — `setWebhook` на **тот же адрес с тем же секретом**; после выкладки — новое меню команд. Адрес webhook cron не меняет и не ставит с нуля (если webhook не задан — только помечает `missing`). Итог (без секретов) — в админке и `/api/health` (`bot.webhook`, `callbackQuery`, `serverSecret`, `confirmed`).
7. Проверка после деплоя (подставить origin). Сначала `https://<origin>/api/health`: `version.commit` — выложенный коммит, `migration` — последняя применённая миграция (`0009_bot_quiz.sql`), `bot` — состояние webhook. Затем картинки:
   ```
   for f in start lesson map words quests profile settings help stop reminder-lesson reminder-streak reminder-return; do
     curl -sS -o /dev/null -w "$f.jpg %{http_code} %{content_type} %{size_download}\n" "https://<origin>/bot/commands/$f.jpg"
   done
   ```
   Ожидается `200 image/jpeg` у всех двенадцати. `200 text/html` значит, что файла нет в сборке. То же для `scenes/ru/{start,return,lesson,words,settings,shopping,food,transport}.jpg` и их `@640.jpg`.
8. Затем написать боту `/start`, `/lesson` … `/stop`, `/quiz` с телефона (iOS и Android), нажать каждую кнопку и ответить на вопрос.

В BotFather руками ничего менять не нужно: команды и webhook ставит сервер; Description Picture остаётся прежней (через API не меняется).

## 8. Решения, о которых нужно знать

* Формулировки взяты из чата задания, расклад — из файла ТЗ; в напоминание добавлена строка «/stop».
* Польский текст `/start` — нейтральный по роду («No to jedziemy!»), без «gotowy/gotowa».
* `/start` без `ref_` пользователя **не создаёт**: запись появляется при первом входе в Mini App, чтобы бот не плодил пустые учётные записи. Сам `/start` без записи показывает приглашение.
* Язык по умолчанию — `uk` (как у продукта).
* Заготовка уведомлений из stash «wip-agents» (миграция 0008, `content/notifications.ts`) **не использована**: она крупнее и о другом (админ-кампании). Здесь своя узкая миграция 0008. Админ-превью и кампании — отдельный этап.
