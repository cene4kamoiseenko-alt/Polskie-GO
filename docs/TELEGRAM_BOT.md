# Telegram-бот POLSKI GO: команды, картинки, напоминания

Задание владельца — `docs/PROMPT_TELEGRAM_BOT.md` (дословно), ТЗ и комплект — `docs/bot/`. Здесь описано, что реализовано, как это развернуть и что **ещё не проверено**.

> Бот в Telegram обновится только после деплоя сервера и (для списка команд) запуска `bot:setup`. Пока изменения не развёрнуты, живой бот работает по-старому.

## 1. Что умеет бот

Девять команд. Каждая отвечает **фото 1280×720 + подпись + inline-кнопки**; кнопки в личном чате — `web_app` и открывают нужную вкладку Mini App.

| Команда | Картинка | Кнопки (экран Mini App) | Данные |
|---|---|---|---|
| `/start` | `start.jpg` | Начать путешествие (`home`), Мои уроки (`learn`), Карта Польши (`map`) | имя из Telegram; повторно — «С возвращением» + следующий урок |
| `/lesson` | `lesson.jpg` | Продолжить обучение (`learn`), Выбрать город (`map`), Повторить слова (`dictionary`) | реальное название и город следующего урока |
| `/map` | `map.jpg` | Открыть карту (`map`), Мои уроки (`learn`) | — |
| `/words` | `words.jpg` | Словарь (`dictionary`), Сленг (`slang`), Грамматика (`grammar`) | — |
| `/quests` | `quests.jpg` | Мои задания (`quests`), Достижения (`achievements`), Пойти на урок (`learn`) | только реальные активные задания и награды; ничего не выдумывается |
| `/profile` | `profile.jpg` | Профиль (`profile`), Достижения (`achievements`), Продолжить / Начать первый урок (`learn`) | уровень, XP, серия, уроки из БД; новичку — приглашение |
| `/settings` | `settings.jpg` | Открыть настройки (`settings`), Вернуться к урокам (`learn`) | — |
| `/help` | `help.jpg` | Открыть POLSKI GO (`home`), Начать урок (`learn`), Настройки (`settings`) | также ответ на неизвестную команду и на текст в личном чате; после карточки ставится панель быстрых кнопок (как и после `/start`) |
| `/stop` | `stop.jpg` | Настроить напоминания (`settings`), Продолжить обучение (`learn`) | выключает **только** учебные напоминания |

* **Постоянная панель быстрых кнопок** под полем ввода: 📚 Урок, 🗺 Карта, 📖 Слова / 🎯 Задания, 🏆 Профиль, ⚙️ Настройки (две строки по три, на ru/uk/pl/en). Она ставится отдельным коротким сообщением («Быстрое меню внизу…») **после карточки `/start` и `/help`** в личном чате (у сообщения не может быть двух клавиатур) и остаётся в чате (`is_persistent`). Нажатие отправляет обычный текст с подписью; бот узнаёт её на любом из четырёх языков и отвечает карточкой соответствующей команды (картинка + inline-кнопки Mini App). В группах панели нет; сбой отправки панели ответ не ломает и карточку не повторяет. Код: `apps/server/src/bot/panel.ts`. Панель — дополнение к ТЗ по просьбе владельца («удобные кнопки»); inline-кнопки под карточками остаются.
* `/stop` ничего не удаляет: прогресс, серия, Premium сохраняются. Кнопка «Настроить напоминания» открывает настройки, **не включает** рассылку. Ответ «напоминания выключены» уходит только после успешной записи в БД; при сбое БД бот честно пишет, что не получилось (без картинки).
* Реферальные ссылки: `t.me/<бот>?start=ref_CODE` — реферера записывает сервер по подписанному webhook (только в личном чате, формат `ref_[A-Za-z0-9]{1,32}`). Параметр `/start <payload>` (`^[A-Za-z0-9_-]{1,64}$`) попадает в `startapp` кнопки главного экрана, прежние ссылки работают.
* Языки текстов: `ru`, `uk`, `pl`, `en`. Выбор: сохранённая настройка пользователя → `language_code` Telegram → `uk` (язык по умолчанию продукта). Имя экранируется (`<`, `&`, `>`, кавычки; управляющие и bidi-символы убираются; до 64 знаков).
* Группы: `web_app`-кнопки там недоступны, поэтому кнопки — обычные ссылки `https://t.me/<бот>/<приложение>?startapp=screen_<экран>`. Бот отвечает только на команды, адресованные ему (фильтр `@имя` работает, когда задана `TELEGRAM_BOT_USERNAME`).
* Заблокированный (`banned`) пользователь не получает ответов. Сбой БД не лишает ответа: `/start`, `/help`, `/map` и т.п. отвечают без персональных данных; `/profile` не изображает «нет прогресса», а говорит, что не смог загрузить.

Тексты — `apps/server/src/bot/copy.ts` (`COPY[lang]`), каталог — `apps/server/src/bot/catalog.ts`, обработчик — `apps/server/src/bot/handler.ts`, отправка — `apps/server/src/bot/send.ts`, данные — `apps/server/src/bot/data.ts`, меню команд — `apps/server/src/bot/commands.json` (ru/uk/pl/en).

## 2. Картинки

Файлы лежат в `apps/web/public/bot/commands/` и публикуются Workers Static Assets на origin приложения (`WEB_APP_URL`):

```
https://<origin>/bot/commands/start.jpg   lesson.jpg   map.jpg   words.jpg   quests.jpg
                               profile.jpg settings.jpg help.jpg  stop.jpg
                               reminder-lesson.jpg  reminder-streak.jpg  reminder-return.jpg
```

* Адрес картинки строится как `new URL('/bot/commands/<файл>', new URL(WEB_APP_URL).origin)`. Фото отправляется **только** если адрес — `https` (локально, при `http://localhost`, уходит текст с теми же кнопками). Telegram скачивает файл сам, авторизация не нужна.
* Подпись к фото ≤ 1024 знаков. Если текст длиннее, уходит короткая подпись (первый абзац) и отдельное сообщение с остальным текстом и кнопками.
* Если Telegram отверг сам снимок (HTTP 400/404 и т.п.: адрес недоступен, не JPEG) — тот же текст и те же кнопки уходят обычным сообщением. Блокировка бота (403), лимит (429), сбой Telegram (5xx) и неопределённый исход сети в текст **не** превращаются: иначе пользователь мог бы получить дубль.
* `wrangler.jsonc` использует `not_found_handling: single-page-application`: если файла нет, сервер вернёт `index.html` со статусом 200. Поэтому после деплоя проверять надо **Content-Type: image/jpeg**, а не только 200 (команда ниже).
* Description Picture (картинка в «Что умеет этот бот?») через Bot API не меняется и не затрагивается.

**Честно про набор:** это промежуточный стартовый комплект владельца, часть кадров повторяется (проверено по md5):

| Одинаковые файлы |
|---|
| `start.jpg` = `settings.jpg` |
| `lesson.jpg` = `quests.jpg` = `reminder-lesson.jpg` |
| `profile.jpg` = `reminder-streak.jpg` |
| `stop.jpg` = `reminder-return.jpg` |

Уникальные кадры: `help`, `words`, `map` (и по одному на каждую группу выше). Позже любой файл можно заменить, код не меняется.

## 3. Mini App: параметр `bot_screen`

Кнопка бота открывает `WEB_APP_URL?bot_screen=<экран>`. Белый список (`packages/shared/src/botScreens.ts`): `home` (без параметра), `learn` → `/learn`, `map` → `/map`, `dictionary` → `/dictionary`, `slang` → `/slang`, `quests` → `/quests`, `profile` → `/profile`, `achievements` → `/achievements`, `settings` → `/settings`, `grammar` → `/grammar`.

* Любое другое значение игнорируется (остаёмся на `/`), параметр убирается из адреса.
* Запасной канал для групповых ссылок: `startapp=screen_<экран>`.
* Не смешивается с `startapp` / `ref_` / `story_` / `premium`: рефералы, истории и Premium работают как раньше.
* Новичок сначала проходит знакомство; затем (`Onboarding.finish`) открывается запрошенный экран, а не первый урок. Повторный запуск идёт прямо на экран. Пока маршрут не применён, вместо `Routes` показывается скелетон (без мелькания главной).
* Код: `apps/web/src/lib/launch.ts`, `apps/web/src/App.tsx`, `apps/web/src/screens/Onboarding.tsx`.

## 4. Идемпотентность webhook

Таблица `telegram_updates(update_id PK, created_at)`. Обновление-сообщение обрабатывается один раз (платежи не дедуплицируются здесь — их защищает своя логика). При временном сбое Telegram (код 0 / 429 / 5xx) метка снимается и возвращается 503, чтобы Telegram повторил доставку; при 400/403 возвращается 200 без повторов. Сбой самой таблицы не блокирует ответ. Cron удаляет строки старше 3 дней.

Платежи Stars (`pre_checkout_query`, `successful_payment`, `refunded_payment`) остались как были.

## 5. Напоминания (`apps/server/src/jobs.ts`)

Cron `*/15 * * * *`. Три сценария, выбираются по реальным данным:

| Вид | Условие | Картинка | Кнопка |
|---|---|---|---|
| `return` | не заходил ≥ 3 дней | `reminder-return.jpg` | Вернуться в игру (`home`) |
| `streak` | эффективная серия ≥ 2 | `reminder-streak.jpg` | Продолжить серию (`learn`) |
| `lesson` | иначе | `reminder-lesson.jpg` | Продолжить урок (`learn`) |

Правила:
* Только при согласии (`user_settings.notifications_enabled`), в выбранный час и часовой пояс пользователя; не более одного напоминания в день (уникальный ключ `(user_id, kind='daily_reminder', day)` в `notification_log`).
* К тексту добавляется строка про `/stop`.
* Ложной записи «отправлено» нет. Состояния строки `notification_log.status`:

| Статус | Значение |
|---|---|
| `PENDING` | заявка на отправку; аренда (lease) 5 минут, так два параллельных Cron не пошлют дубль |
| `SENT` | Telegram принял; сохраняются метод (фото/текст), `telegram_message_id`, время |
| `FAILED` | точный сбой (429 / 5xx): повтор в тот же местный день, до `NOTIFY_MAX_ATTEMPTS=3`, паузы 5 / 20 минут или `retry_after` |
| `BLOCKED` | 403 (бот заблокирован): пользователь пропускается 30 дней |
| `UNKNOWN` | неопределённый исход (сеть/таймаут, истёкшая аренда): **не повторяется**, чтобы не отправить дубль |
| `SKIPPED` | `day_passed`, `consent_withdrawn` (согласие отозвано), `already_active` |
| `LEGACY` | строки до миграции 0008 |

* Бюджет подзапросов Worker: `SEND_BUDGET=35` вызовов Bot API за запуск (фото + запасной текст = 2).
* Миграция `0008_bot_delivery.sql` **только добавляет**: таблицу `telegram_updates`, колонки `notification_log` (старые строки получают `LEGACY`), индекс. Ничего не удаляет и не переписывает.

## 6. Развёртывание

1. **Тесты, typecheck, content-lint** перед пушем (см. ниже). Пуш в ветку запускает Cloudflare Workers Builds и деплоит.
2. Деплой (`npm run deploy:cf` или Workers Builds) применяет миграцию 0008 к D1 **после** `wrangler deploy`. Окно между выкладкой кода и миграцией: до миграции у `notification_log` нет новых колонок — напоминания и дедупликация в это время могут давать ошибку; Telegram повторит обновления сам, а Cron повторит запуск через 15 минут. Если деплой идёт вручную, применить миграцию сразу: `wrangler d1 migrations apply polski-go --remote`.
3. Переменные Cloudflare (не менять без причины): `WEB_APP_URL` (полный адрес с `https://`; если указан без схемы или с `http://`, сервер и `bot:setup` сами приведут его к `https://`, `localhost` остаётся на http и тогда фото не уходят), `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `TELEGRAM_BOT_USERNAME`, `TELEGRAM_APP_SHORT_NAME`.
4. После деплоя владелец один раз запускает локально (секреты берутся из окружения/`.env`, в вывод не попадают):
   ```
   WEB_APP_URL=https://<origin> TELEGRAM_BOT_TOKEN=… npm run bot:setup -w @polski-go/server
   ```
   Что делает по умолчанию: `setMyCommands` — девять команд (ru по умолчанию + uk/pl/en) и `setChatMenuButton` (кнопка запуска Mini App). Затем только читает `getWebhookInfo` / `getMyCommands`.
5. Флаги:
   * `--dry-run` — показать вызовы без сети (токен не нужен);
   * `--webhook` — установить webhook (нужны `PUBLIC_URL`, `TELEGRAM_WEBHOOK_SECRET`); `allowed_updates=["message","pre_checkout_query"]`, ожидающие обновления **не** сбрасываются. Нужен только если webhook ещё не задан или меняется адрес;
   * `--description` — перезаписать описание бота текстом по умолчанию. Без флага описание, заданное вручную в BotFather, остаётся нетронутым.
6. Скрипт **не** меняет токен, webhook (без `--webhook`), About, Description Picture.
6a. **Без компьютера и без токена в ссылках** (самонастройка из Worker). Работает токеном из Cloudflare и защищена секретом webhook:
   ```
   https://<origin>/telegram/setup?key=<TELEGRAM_WEBHOOK_SECRET>             # ставит команды (ru + uk/pl/en), кнопку меню и webhook
   https://<origin>/telegram/setup?key=<TELEGRAM_WEBHOOK_SECRET>&mode=check  # только читает: getMe и getWebhookInfo
   ```
   Ответ — JSON: `ok`, имя бота, шаги (`getMe`, `setMyCommands`…, `setWebhook`, `getWebhookInfo`) с кодом и текстом ошибки Telegram, состояние webhook (адрес без параметров, число ожидающих, последняя ошибка) и `hints` — что исправить (неверный или пустой `TELEGRAM_BOT_TOKEN`, не https `WEB_APP_URL`, недопустимые знаки в секрете, чужой бот, 401 от сервера). Токен и секрет в ответ не попадают (проверено тестом). Тот же набор вызовов, что у `bot:setup --webhook`, описание бота и Description Picture не меняются. Без верного ключа — 401, без `TELEGRAM_WEBHOOK_SECRET` — 503. Ключ попадает в историю браузера и журнал запросов Cloudflare: после настройки при желании смените секрет в Cloudflare и повторите ссылку.
7. Проверка после деплоя (подставить origin):
   ```
   for f in start lesson map words quests profile settings help stop reminder-lesson reminder-streak reminder-return; do
     curl -sS -o /dev/null -w "$f.jpg %{http_code} %{content_type} %{size_download}\n" "https://<origin>/bot/commands/$f.jpg"
   done
   ```
   Ожидается `200 image/jpeg` у всех двенадцати. `200 text/html` значит, что файла нет в сборке.
8. Затем написать боту `/start`, `/lesson` … `/stop` с телефона (iOS и Android) и нажать каждую кнопку.

В BotFather руками ничего менять не нужно, **кроме** случаев: (а) `/setcommands` теперь не нужен — команды ставит скрипт; (б) если у бота не задан webhook — флаг `--webhook`; (в) Description Picture остаётся прежней (через API не меняется).

## 8. Решения, о которых нужно знать

* Формулировки взяты из чата задания, расклад — из файла ТЗ; в напоминание добавлена строка «/stop».
* Польский текст `/start` — нейтральный по роду («No to jedziemy!»), без «gotowy/gotowa».
* `/start` без `ref_` пользователя **не создаёт**: запись появляется при первом входе в Mini App, чтобы бот не плодил пустые учётные записи. Сам `/start` без записи показывает приглашение.
* Язык по умолчанию — `uk` (как у продукта).
* Заготовка уведомлений из stash «wip-agents» (миграция 0008, `content/notifications.ts`) **не использована**: она крупнее и о другом (админ-кампании). Здесь своя узкая миграция 0008. Админ-превью и кампании — отдельный этап.
