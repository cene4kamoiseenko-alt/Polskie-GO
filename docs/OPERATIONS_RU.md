# Эксплуатация: защита, резервные копии, откат, мониторинг

Состояние на 2026-11-04. Проект на **бесплатном плане** Cloudflare Workers (`wrangler.jsonc`). Пуш в ветку `claude/polski-go-telegram-app-r8helf` собирает и выкладывает production (Workers Builds → `npm run deploy:cf`).

## 2. Что сделать вам (один раз; из среды разработки этого не сделать)

1. **Двухфакторная защита** на аккаунтах Cloudflare, GitHub и Telegram (аккаунт, которому принадлежит бот). Проверьте, у кого есть доступ к Cloudflare и репозиторию.
2. **R2 закрыт:** Cloudflare → R2 → `polski-go-audio` → Settings → *Public access*: **Disabled**, *r2.dev subdomain*: **Disabled**. Файлы озвучки отдаёт только Worker.
3. **Ночная резервная копия** (`.github/workflows/d1-backup.yml`):
   - GitHub → Settings → Environments → **production-backup** → секреты `CLOUDFLARE_API_TOKEN` (токен с правом *D1: Edit*, только на этот аккаунт), `CLOUDFLARE_ACCOUNT_ID`, `BACKUP_PASSPHRASE` (длинный пароль; сохраните его вне GitHub — без него копию не открыть);
   - расписание GitHub запускает **только из основной ветки**: задача заработает после слияния в `main`. До этого — ручная копия (раздел 3);
   - первый запуск — вручную: Actions → *D1 backup (nightly)* → *Run workflow*, затем учебное восстановление скачанной копии (раздел 4).
4. **Staging** (необязательно, но лучше до запуска): `docs/STAGING.md`, раздел 5 — база `polski-go-staging`, секреты, `npm run deploy:staging`.
5. **Дополнительное WAF-правило** (необязательно: ограничители в Worker уже есть): Security → WAF → Rate limiting rules → путь `/api/admin/login` — 10 запросов в минуту с IP, действие *Block* на 10 минут.
6. **Уведомления Cloudflare:** Notifications → Add → *Workers* (ошибки/превышения) на вашу почту — что доступно на бесплатном плане.

## 3. Резервные копии

- **Ночная копия** (после шага 2.3): каждую ночь в 02:17 UTC экспорт production-базы → gzip → шифрование AES-256 паролем → артефакт GitHub на 30 дней.
  Во время экспорта D1 не отвечает на запросы (секунды при нынешнем объёме) — поэтому ночью.
- **Ручная копия** на ваш компьютер: `npx wrangler login`, затем `npm run backup:d1` → `backups/polski-go-<дата>.sql` (папка не попадает в git). В копии — данные игроков: храните её как пароль.
- **Time Travel** (без копий): восстановление на любую минуту за последние 7 дней — раздел 5.

## 4. Проверка восстановления (раз в месяц и после изменения схемы)

```bash
npm run restore:drill -- --self-test            # без Cloudflare: миграции + seed → экспорт → чистая база → сверка таблиц
BACKUP_PASSPHRASE=… npm run restore:drill -- polski-go-<дата>.sql.gz.gpg   # настоящая ночная копия
```

Скрипт заливает копию в **локальную** базу (Cloudflare не трогает), печатает число строк по таблицам игроков и прогресса и пишет файл
в правильном порядке (`.wrangler/restore-drill/restored.ordered.sql`).

**Важно (найдено учебным восстановлением 2026-11-04):** «сырой» экспорт `wrangler d1 export` в пустую базу **не заливается** —
таблицы в нём по алфавиту, и `exercises` со строками идёт раньше `lessons` (ошибка `no such table: main.lessons`). Скрипт переставляет:
сначала все таблицы, потом строки, потом индексы и триггеры. Для аварийного восстановления в новую базу используйте **только этот файл**.

## 5. Откат

**Сломалась выкладка (код), база в порядке** — откатить только код:
1. Cloudflare → Workers → polskie-go → Deployments → предыдущая версия → *Rollback* (или `npx wrangler rollback`). Статические файлы откатываются вместе с версией.
2. Проверить `/api/health` (коммит) и открыть приложение.
3. Исправить причину в ветке; следующий пуш выкладывает исправление.

**Испорчены данные (ошибочная миграция, массовая правка в админке)** — откатить код и базу:
1. Сначала код (как выше), иначе испорченная логика продолжит писать.
2. Найти закладку из журнала сборки этой выкладки (строка `bookmark` из `wrangler d1 time-travel info` в начале `deploy:cf`) или выбрать время.
3. `npx wrangler d1 time-travel restore polski-go --bookmark=<закладка>` (или `--timestamp=2026-11-04T10:00:00Z`).
4. **Всё, что игроки сделали после этой точки, пропадёт**, в том числе платежи Stars: сверить журнал платежей Telegram и при необходимости выдать Premium вручную (админка → пользователь → Premium).
5. Команда печатает закладку «до восстановления» — с ней можно вернуть базу обратно, если откат был лишним.

**База удалена или вне окна 7 дней** — создать новую базу, залить файл из раздела 4 (`npx wrangler d1 execute <новая база> --remote --file restored.ordered.sql`),
поменять `database_id` в `wrangler.jsonc`, выложить.

## 6. Мониторинг и разбор инцидента

1. **Админка → Обзор → «Ошибки за 24 часа»**: сервер / приложение / CSP, сообщение, путь, сколько раз, когда последний раз. Пусто — зелёное «нет».
2. **Workers Logs** (Cloudflare → Workers → polskie-go → Logs): полный стек серверных ошибок, ошибки cron (напоминания, очистка).
3. **`/api/health`**: какой коммит работает, применена ли последняя миграция, бот, сколько озвучки готово.
4. Сломался вход у многих сразу — проверить ограничители: ответ `429 rate_limited` на `/api/auth/telegram`. Лимит 60/мин на IP рассчитан на мобильный NAT;
   при массовом запуске его можно поднять в `wrangler.jsonc` (`RL_AUTH` → `limit`) и выложить.
5. После инцидента — запись в `docs/QA_RESULTS.md`: что случилось, как заметили, что исправили.

## 6а. Нагрузка

`npm run load:test` — 500 виртуальных игроков против локального Worker (`docs/LOAD_TEST_RU.md`): проверяет логику под параллельной записью (награды, баланс, двойные нажатия). Перед открытием для игроков прогнать тот же скрипт на **staging** (`LOAD_BASE_URL=…`) и посмотреть в Cloudflare CPU time и ошибки 1102: на бесплатном плане лимит 10 мс CPU на запрос, `/api/journey` — самый тяжёлый.
