2. ОСНОВНАЯ ЗАДАЧА: ЕДИНЫЙ ЖИВОПИСНЫЙ 2.5D-БОБЕК
Важное решение владельца уже принято в docs/CLAUDE_HANDOFF.md: НЕ делать плоский векторный SVG-риг вместо персонажа. Не подключать платные API для генерации. Нужен один добрый живописный персонаж как на исходных скриншотах/референсах: орехово-коричневый мех, большая округлая голова, круглые блестящие глаза, светлая мордочка, две видимые передние зубки, небольшие круглые уши, розовые щёки, широкий плоский клетчатый хвост; постоянные размеры, лицо и пропорции.

Требования:
• Напиши docs/ADR-005-PAINTERLY-BEAVER.md, сравни подходы и выбери реально реализуемый архитектурный путь: базовая живописная модель, согласованные визуальные слои одежды, точки крепления/anchors, корректный z-index, прозрачность, маски и общий manifest ассетов.
• Централизуй состояние внешнего вида: resolveLook(user, inventory, equipment), tryOn(current, candidate), equip/unequip, compatibility rules. Не допускай ручных подмен костюма по имени в Home/Map/Shop/Profile/Missions.
• Раздели базовый персонаж, тело, голову, верхнюю одежду, низ, головные уборы, обувь, рюкзак, очки и аксессуары. Полный костюм может занимать несколько слотов; правила конфликтов должны быть явными. Один и тот же предмет должен выглядеть одинаково на одном ракурсе и не менять морду персонажа.
• Предпросмотр не сохраняет покупку или экипировку до подтверждения. Вещь должна визуально меняться именно на выбранную вещь, а не на предыдущий костюм. После подтверждения единый внешний вид отображается на главной, карте, профиле, в гардеробе и совместимых миссиях.
• На время перехода разрешено использовать уже существующие качественные живописные готовые образы для целых костюмов. Не ухудшай их до плоского SVG. Но они должны быть явно помечены как legacy whole-look fallback, а не выдаваться за реально совмещаемые слои. Если для отдельной вещи отсутствует совместимый живописный слой — честно покажи «визуал готовится», сохрани владение и стоимость/историю, не отображай произвольную неправильную одежду и не потеряй покупку.
• Реализуй один проверенный эталон: базовый Бобек + красное худи PL + кепка + рюкзак + обувь, затем костюм бариста и повара. Не переноси весь каталог до проверки эталона.
• Зафиксируй DOM/data-look контракт и единые исходные данные по надетому образу. Создай gallery QA и визуальные снимки всех ракурсов, экипировки, конфликтов и старых состояний. Не смешивай PNG/WebP-анимацию с SVG-подменой персонажа.

3. БЕСПЛАТНЫЙ ПАЙПЛАЙН ГРАФИКИ (ОЧЕНЬ ВАЖНО)
Прикреплённые визуальные доски — цвет, стиль, композиции и цель. Они НЕ гарантируют одинаковую геометрию и НЕ содержат настоящих независимых прозрачных слоёв. Не вырезай из плаката кусочки и не называй их полноценными слоями одежды. Image-generation output может быть плоским концептом.

Подготовь в репозитории бесплатный asset import pipeline:
• шаблоны для исходных листов Бобека (постоянный canvas, scale, якоря, прозрачный/контрастный фон, одинаковые ракурсы);
• manifests: ID, pose, slot, anchor, dimensions, baseVersion, compatibility, rarity и fallback;
• локальные скрипты нарезки, выравнивания, проверки размеров/alpha и оптимизации в WebP/AVIF;
• контактный лист для ревью владельцем и визуальный регрессионный тест на сдвиг вещей;
• генератор точных текстовых запросов для самостоятельной подготовки владельцем недостающих изображений;
• список недостающих ассетов, без которых невозможно полностью завершить гардероб.

Никаких платных генераторов без отдельного согласия. Не обещай автоматом получить корректный 2.5D риг из одного коллажа; если требуется исходный artwork, честно укажи это и продолжай независимые задачи.

4. АНИМАЦИИ БОБЕКА: НЕ КОСМЕТИКА, А ЧАСТЬ ИГРЫ
Создай систему состояний (idle, wave, blink, happy, correct, wrong, thinking, listening, speaking, walking, celebrating, outfitTryOn, levelUp, sleep/offline). Не нужно одновременно запускать все эффекты.

Визуальные требования:
• Idle: редкое мягкое моргание, дыхание, микронаклон головы, при возможности слабое движение хвоста; без непрерывного «дёрганья».
• Приветствие: поднятие лапы и мягкий наклон головы при входе/встречe.
• Правильный ответ: улыбка, короткий bounce, аккуратная искра/XP; интерфейс мгновенно сообщает успех.
• Неправильный ответ: доброжелательное выражение и короткое покачивание без наказания/стыда, затем объяснение.
• Прослушивание/речь: индикатор микрофона и лёгкая реакция персонажа только при реальном событии записи; не изображай успешное распознавание без результата.
• Получение костюма: краткая анимация примерки с подтверждением; надетый предмет остаётся на том же бобре.
• Повышение уровня: небольшая торжественная анимация, конфетти с ограниченным временем, награда от сервера.
• Карта: Бобек идёт/двигается между городами только в момент реального прогресса, не телепортируется поверх неоткрытых этапов.

Предложи motion tokens: длительности примерно 120–260 мс для кнопок, 250–450 мс для карточек, до 700–1000 мс для редких наград (как ориентиры, после тестов можно менять). Используй в первую очередь transform и opacity, а не дорогие эффекты. Реализуй prefers-reduced-motion, запрет анимации при скрытой вкладке, cleanup эффектов и проверку производительности в iOS Telegram WebView.

ВАЖНО: static art + CSS transform не равно настоящая покадровая ходьба. Если для walking нужны дополнительные совместимые кадры — подготовь pipeline и честно пометь зависимость от ассетов. Не скрывай ограничение под фальшивым переключением несвязанных картинок.
