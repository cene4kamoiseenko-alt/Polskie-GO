## 3. Быстрые вопросы (/quiz)

Полный цикл: `/quiz` → вопрос (фото только у трёх тем и только для русского интерфейса, иначе текст) → кнопки вариантов → нажатие (`callback_query`) → проверка → пояснение → XP → D1 → Mini App видит XP в профиле и заданиях → «Следующий вопрос».

- 60 вопросов A1–B1, уровень по ученику, недавние вопросы и тема прошлого не повторяются; правильный вариант перемешивается (не «всегда B»).
- Тренировка не блокируется: 3-часовая пауза относится **только** к приглашениям, которые бот присылает сам. Ограничения ручной игры — только против спама: не чаще раза в 4 с и не больше 30 вопросов за местный день.
- Награда ограничена: +10 XP только за первые 3 верных ответа вовремя за местный день; дальше — «без XP», учиться можно.
- Один ответ на вопрос: раунд OPEN → ANSWERED условным UPDATE; повторная доставка Telegram, двойное нажатие и два одновременных нажатия не дают второй награды; на повторное нажатие бот отвечает «Ответ уже засчитан», на кнопки старого вопроса — «Этот вопрос устарел. Новый — по команде /quiz».
- Приглашения (cron): только с согласия на уведомления, в 13:00 местного времени (17:00, если напоминание стоит на 12–14), не раньше чем через 3 часа после последнего вопроса, не тем, кто дважды проигнорировал, не заблокировавшим бота; не больше одного в местный день (журнал доставки `notification_log`).
- Серия дней от вопроса не растёт (её продлевают уроки и миссии).

Тесты: `bot-quiz.test.ts` (18) — с подменённым Telegram. На реальном телефоне не проверено.

## 4. Безопасность webhook

- Секрет webhook генерирует сервер (32 случайных байта), хранит только в D1 (`app_state`), в логи и ответы не выводит; сравнение в постоянное время.
- Заголовок `X-Telegram-Bot-Api-Secret-Token` проверяется на каждом запросе; без него — 401.
- `allowed_updates` включает `message`, `callback_query`, `pre_checkout_query`.
- Ротация — только при отсутствии состояния или по явной команде администратора, **не на каждом cron**. Механизм восстановления: старый секрет продолжает приниматься 6 часов, пока новый не подтверждён успешным `setWebhook`; после подтверждения — 10 минут. Если Telegram отклонил `setWebhook` (4xx), прежний секрет восстанавливается.
- Страница настройки `/telegram/setup`: ключ — только в заголовке (`?key=` в адресе отклоняется с 400), лимит 10 попыток за 10 минут, `no-store`, `noindex`, `no-referrer`. Ключ — `BOT_SETUP_KEY`; запасной вариант через старый `TELEGRAM_WEBHOOK_SECRET` работает только пока сервер ещё не завёл свой секрет. Основной путь — админка «🤖 Бот» (вход администратора, аудит без секретов).
- Самовосстановление в cron: переустанавливает webhook только в безопасных случаях (нет состояния, нет `callback_query`, 401 после установки, неподтверждённый секрет).
- Ключ Google TTS (и новый Google STT) передаётся в заголовке `X-Goog-Api-Key`, а не в адресе запроса.

**Webhook из этой среды не перенастраивался и не проверялся:** доступа к `api.telegram.org` и к production-адресу нет (прокси отвечает 403). Перенастройка произойдёт сама при первом cron после деплоя (каждые 15 мин) — это нужно подтвердить (раздел 9).

## 5. Миграция 0009

`0009_bot_quiz.sql` — только `CREATE TABLE` (`app_state`, `bot_quiz_players`, `bot_quiz_rounds`) и `CREATE INDEX`; ни одна существующая таблица не меняется. Номер 0009 в репозитории один; применённые миграции не правились.

Проверено:
- `migration-0009.test.ts`: база до 0008 + seed, данные пишет настоящий код (вход, настройки, миссия с XP, Złotki, задания, достижения) → снимок всех таблиц → 0009 → каждая прежняя таблица побайтно та же, новые пустые, `PRAGMA quick_check` = ok, `foreign_key_check` пуст, прогресс через API тот же, `/quiz` работает.
- Реальный `wrangler d1 migrations apply --local` на копии с 200 синтетическими пользователями: контрольные суммы XP, уровней, серий, заданий, достижений до/после совпали; повторный запуск — «No migrations to apply».

Бэкап и откат: D1 Time Travel (Free — 7 дней, Paid — 30). Команда деплоя сначала печатает закладку (`wrangler d1 time-travel info`), затем применяет миграции, затем выкатывает код. Откат данных: `npx wrangler d1 time-travel restore polski-go --timestamp=<время до деплоя>`; откат кода — предыдущая версия в Cloudflare → Workers → polskie-go → Deployments. Новые таблицы старый код не читает, так что откат кода без отката данных безопасен.

**Применена ли в production:** сборка `6a516d59` завершилась успешно и выпустила версию `85a4eab5`. В команде деплоя `wrangler deploy` идёт после `migrations apply --remote` через `&&`, поэтому успешная версия означает, что применение миграций завершилось без ошибки. Сам журнал `d1_migrations` в production отсюда не читался — подтверждение: `/api/health` → `migration` должен быть `0009_bot_quiz.sql`.

## 10. Действия владельца

1. Открыть `https://polskie-go.cene4kamoiseenko.workers.dev/api/health`: `version.commit` — последний коммит, `migration` — `0009_bot_quiz.sql`, `bot` — webhook установлен, `callback_query` есть, секрет подтверждён.
2. Админка → «🤖 Бот» → «Перевірити». Если webhook не обновился за 15 минут — «Налаштувати бота».
3. На телефоне (iOS и Android): `/start`, `/quiz`, нажать вариант, «Следующий вопрос», затем в Mini App проверить XP и задание «Получи 100 XP».
4. По желанию: задать `BOT_SETUP_KEY` (Secret) для страницы `/telegram/setup`; старый `TELEGRAM_WEBHOOK_SECRET` после перехода на серверный секрет больше не нужен — его можно удалить.
5. Если токен бота когда-либо попадал в чат или логи — перевыпустить в @BotFather (`/revoke`) и обновить `TELEGRAM_BOT_TOKEN`.
6. Чтобы следующая сессия могла сама проверять production: в настройках среды Claude разрешить сетевой доступ к `polskie-go.cene4kamoiseenko.workers.dev` и `api.telegram.org`.
7. Передать экспорт работы Sonnet (раздел 1), если она ещё существует.
8. Google: решение о биллинге; подключение TTS — `docs/POLISH_TTS_BENCHMARK.md`, STT — `docs/AUDIO_SETUP_RU.md`.
9. Картинки: мастер-файлы городов Gorzów и Gdynia и версии кадров бота без текста — промпты в `NEXT_APP_ROADMAP.md`.
