# POLSKI GO — инструкции для Claude

## Агенты и модели

Профильные агенты лежат в `.claude/agents/`. Модель и усилие заданы во frontmatter (поля `model` и `effort`): сильный уровень модели и усилие `xhigh` (Extra high) у всех, включая механические запуски. Это решение владельца: не `max`, не `high` и не ниже ради экономии лимитов. Усилие основной сессии задаёт владелец командой `/effort xhigh`. Если агент запускается не по профилю, модель и усилие передаются параметрами при вызове.

Основная сессия: разделы 1 и 26, распределение задач, приёмка, коммиты, документы `PROJECT_PROGRESS.md`, `docs/CLAUDE_HANDOFF.md`, `docs/QA_RESULTS.md`, `docs/RELEASE_CHECKLIST.md`.

Правила распределения:
- Тяжёлые прогоны (e2e, screens, a11y, perf) — по одному, чтобы не упираться в лимит. Одну и ту же проверку не гоняют параллельно разные агенты.
- Один файл — один редактор. Два агента не правят один и тот же файл одновременно.
- Агенту передаются конкретные файлы, задача и критерии приёмки.
- Результат агента проверяет основной Claude: typecheck и затронутые тесты запускаются заново, прежде чем коммит.

## Жёсткие правила

- Не `git reset --hard`, не `clean -fd`, не force push, не разрушительные миграции БД.
- Не делать production release и реальные финансовые изменения без согласования.
- Dev auth endpoints не попадают в production.
- Секреты и токены не печатаются и не попадают в отчёты.
- «Тесты зелёные» — только после реального запуска. «Проверено на iPhone» — только при реальном устройстве.
- Коммит трейлеры: без названия модели; `Claude-Session:` со ссылкой на текущую сессию.
- PR не создавать без запроса.
- Пуш в ветку деплоит (Cloudflare Workers Builds): перед пушем typecheck, тесты, content-lint.
